# v0.1 local contract (draft)

This document freezes the **local-first** surface for IntentProof `v0.1.0`.
Hosted control-plane behavior is out of scope (see workspace `SCOPE.md`).

## Bundle archive

- Format: tar inside zstd (`.proof.tar.zst`), or plain tar for tests.
- Required manifest: `manifest.json` with file SHA-256 entries and Merkle roots.
- Core members: `flow.json`, `events.jsonl`, `policy.json`, `run.json`.
- Optional: `attestations.jsonl`, `certificate.json`, `keys/*.pub`.

## Offline verification (`intentproof-verify`)

| Command | Purpose | Exit code |
|---------|---------|-----------|
| `intentproof-verify <bundle>` | Structural integrity (hashes, Merkle, signatures) | 0 pass, 1 fail |
| `intentproof-verify explain <bundle>` | Integrity + policy replay summary | 0 pass, 1 fail |
| `intentproof-verify replay <bundle>` | Integrity then fresh policy eval (JSON run) | 0 pass, 1 fail |

Machine-readable JSON: `intentproof verify <bundle>` (same integrity semantics).

## Policy replay semantics

- Replay merges `events.jsonl` into the flow document and evaluates `policy.json`
  with the in-tree Go policy evaluator (`pkg/verifier`).
- Replay does **not** replace structural checks; callers must verify integrity
  first for counterparty use.
- Bundled `run.json` is compared for status only in `explain` output.

## Reason catalog

- Stable reason codes are defined in `intentproof-spec/semantics/reasons.json`.
- `explain` enriches findings when `INTENTPROOF_SPEC_DIR` points at a spec checkout.

## Golden fixtures

- Counterparty: `intentproof-spec/golden/counterparty/`
- CI: `scripts/check-counterparty-golden.sh` (stdout hash lock)

## Compatibility

- Breaking changes to manifest layout, hash rules, or verifier exit semantics
  require a minor version bump after `v0.1.0` is tagged.
